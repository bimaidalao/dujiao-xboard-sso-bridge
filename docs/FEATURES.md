# 二开功能详细说明

## 1. Dujiao → Xboard 一键登录

用户在 Dujiao 商城已登录时，跨站入口从浏览器读取当前 `user_token`，使用隐藏 POST 表单提交到 Xboard 的固定 SSO 路由。Xboard 随后：

1. 调用配置的 Dujiao HTTPS/私网身份接口验证 Token；
2. 检查邮箱格式、邮箱验证状态和账号状态；
3. 按小写邮箱查找 Xboard 用户；
4. 没有同邮箱用户时，通过 Xboard 原生 `UserService` 创建普通用户；
5. 从仅限本机的凭据接口读取兼容 bcrypt 哈希；
6. 同步密码字段并清理旧版密码算法、盐字段；
7. 通过 Xboard 原生 `LoginService` 生成快捷登录地址；
8. 只允许跳转到白名单页面。

这条链路不伪造管理员身份，不复制余额、等级、订单或权限字段。

## 2. Xboard → Dujiao 一键登录

用户在 Xboard 已登录时，入口读取当前 `auth_data`，提交到 Dujiao 域名下的 `/sso/xboard`。本机桥接服务随后：

1. 调用配置的 Xboard HTTPS/私网用户接口验证当前会话；
2. 拒绝邮箱无效或已禁用的用户；
3. 读取 Xboard 用户表中的 bcrypt 哈希；
4. 按邮箱匹配或创建 Dujiao 普通用户；
5. 更新 Dujiao 密码哈希和 Token 版本；
6. 使用 Dujiao 自身的用户 JWT 密钥签发短时登录 Token；
7. 把 Token 写入商城使用的 localStorage 键并进入首页。

原生或 Docker host 网络下桥接只监听 `127.0.0.1`；Docker bridge 网络下由安装器检测网关和可信 CIDR。公网只能访问 Nginx 明确暴露的固定路径，不能直接访问密码哈希接口。

## 3. 自动账号创建与映射

账号唯一映射键是规范化后的邮箱：去除首尾空格并转换为小写。自动创建必须同时满足：

- 邮箱格式正确；
- 来源系统已验证邮箱；
- 来源账号未被禁用；
- 目标系统不存在相同邮箱的有效账号。

已存在同邮箱账号时只更新认证所需字段，不重复创建用户。不同邮箱不会因为昵称、Telegram、IP 或设备相似而自动合并。

## 4. 密码共享与独立登录

两个系统使用兼容 bcrypt 时，SSO 直接同步来源站的不可逆哈希。因此账号关联后，用户既可以一键登录，也可以使用同一邮箱和密码分别登录两个网站。

| 用户操作 | 密码结果 |
| --- | --- |
| 商城 → 节点 | 节点密码更新为商城当前密码 |
| 节点 → 商城 | 商城密码更新为节点当前密码 |
| 目标站没有账号 | 新账号直接继承来源站密码哈希 |
| 两边旧密码不同 | 以最后一次发起 SSO 的来源站为准 |
| 修改其中一边密码 | 从改密一侧再跨站一次即可重新同步 |

安全性质：

- 不可从 bcrypt 哈希还原密码明文；
- 桥接不记录、不返回给浏览器密码哈希；
- Xboard 的 `$2y$` 标记可规范化为 Dujiao 验证器兼容的 `$2a$`，哈希主体不变；
- 仅接受格式严格匹配的 bcrypt 哈希，其他算法直接拒绝；
- 密码变化时递增 Dujiao `token_version`，使旧会话按系统规则失效。

## 5. 跳转白名单与失败回退

Dujiao → Xboard 只接受预先列出的目标，例如：

```text
dashboard
tickets
mobile/tickets
plan
```

任意外部 URL、协议字符串或未识别目标都回到默认仪表盘，避免开放重定向。身份校验、哈希格式、数据库或目标账号状态任一步失败，都会回到配置的登录页并写入服务端日志，不在浏览器暴露内部异常。

## 6. 跨站入口卡片

仓库提供无框架依赖的 JavaScript 和 CSS，可注入主题自定义 HTML，也可集成到源码布局：

- 支持站点 Logo、主标题和小字副标题；
- 支持“AI 专用加速器 VPN 节点”“GPT、Gemini、Telegram、Google”等说明；
- 日间/夜间主题自动跟随站点；
- 桌面端可作为完整横向卡片或悬浮卡片；
- 手机端使用紧凑尺寸，放在底部导航右侧上方；
- 避开“回到顶部”按钮；
- 外层容器不接收点击，避免看不见的透明遮罩阻断滑动；
- 未登录时自动跳转到对应登录页。

示例效果见项目首页的三张已脱敏截图。

## 7. 手机端客服与工单入口

工单和 Telegram 客服可以折叠到底部同级菜单，解决多个悬浮按钮挡住手机底部导航的问题：

- 关闭状态使用 `display: none`，不残留透明遮罩；
- 展开层只覆盖自身可见区域；
- 不阻止页面上下滑动；
- 工单入口可以携带当前站用户信息；
- 创建工单时由服务端自动附带两个系统各自最近一笔订单；不能相信浏览器传来的用户 ID 或任意订单号。

## 8. 注册入口强化

登录页中不明显的文字注册链接可以通过主题层增强为高对比按钮：

- 明确标注“注册账号”或“新用户入口”；
- 日间/夜间都保持足够对比度；
- 手机端占据合适宽度；
- 只修改展示层，不绕过原有验证码、邮箱验证或风控逻辑。

## 9. 运维与安全二开

仓库同时提供：

- Nginx 固定路由示例；
- 绑定本机或受控 Docker 私网的 systemd 服务；
- `NoNewPrivileges`、只读路径和最小写目录示例；
- 部署前数据库与文件备份步骤；
- 双向 SSO、密码共享、禁用账号和手机端验收清单；
- 日志关键词、常见故障和完整回滚流程；
- 防止真实 `.env`、数据库、日志和密钥误传 GitHub 的安全边界。

## 10. 未包含的业务功能

以下能力不属于本仓库当前范围：

- 卡密、自动发货正文、支付凭据或完整支付记录写入 Xboard；
- Xboard 套餐、流量和余额反向写入商城；
- 管理员权限共享；
- 不同邮箱账号的自动合并；
- 多服务器公网数据库直连；
- 对上游任意版本的无条件兼容。

当前工单只附带按当前用户鉴权得到的最近订单摘要，不提供跨系统订单管理、支付同步或交付内容读取。
